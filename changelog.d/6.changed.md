**BREAKING**: `unsigned=True` on a numeric type is now refused with `UnsupportedFeatureError` instead of rendering byte-identical signed SQL, and a type string carrying `UNSIGNED` is refused by `parse_type` instead of being read back as signed — Snowflake's numeric inventory has no unsigned row and its column grammar has no modifier after `<col_type>`, so use a `CHECK` constraint as the message says. A bare `VARCHAR` now renders `VARCHAR(16777216)` and a bare `NUMBER` renders `NUMBER(38, 0)` (and `NUMBER(10)` renders `NUMBER(10, 0)`): the manual's documented defaults are written out, which is the same column the server stores and what makes a bare declaration compare equal to what the catalog reports.
