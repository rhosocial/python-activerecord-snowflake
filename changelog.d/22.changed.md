`item_exists()` now classifies every core `ItemKind` instead of refusing the kinds it does not query. Kinds Snowflake has no objects of -- `TYPE`, `DOMAIN`, `INDEX` (there are no secondary indexes), `EXTENSION`, `TABLESPACE`, `PARTITION_FUNCTION`, `PARTITION_SCHEME` and `FULLTEXT_CATALOG` -- answer `False` without issuing a query, while `SCHEMA`, `TABLE` (views excluded), `SEQUENCE` and `FUNCTION` are answered from the catalogue. The refusal branch is now empty, so no kind is refused today; a kind added to core later refuses rather than silently answering `False`.
