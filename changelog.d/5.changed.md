Consume the two-spelling clause pairs with one parameter per spelling: the dialect's sequence, identity, schema, truncate, materialized-view and transaction formatters now read both halves of every pair they own, so `DROP SCHEMA ... RESTRICT` is rendered instead of being dropped. The same rule closes the two Snowflake expression gaps: `SnowflakeCreateFunctionExpression` takes `immutable` / `volatile` and `SnowflakeUnpivotExpression` takes `include_nulls` / `exclude_nulls`; with neither parameter set the clause is omitted, with both set construction raises `ValueError`, `immutable=False` no longer emits `VOLATILE`, `include_nulls=False` no longer emits `EXCLUDE NULLS`, and the explicit negatives are requested as `volatile=True` / `exclude_nulls=True`.
