Fix the defects this refactor exposed: the sequence capability probe was misspelled, so core never consulted it and every sequence statement had been refused; the new boolean pair fields were read with `is not None`, so a bare `IdentityClause()` refused and a bare `ALTER SEQUENCE` emitted `NOORDER`; `supports_transaction_wait()` answered a non-boolean `None`; requested clauses Snowflake cannot express now raise `UnsupportedFeatureError` naming the clause instead of being rendered without it (`BEGIN` / `SET TRANSACTION` `WAIT` / `NO WAIT`, `TRUNCATE` `CASCADE` / `RESTRICT` / `RESTART IDENTITY` / `CONTINUE IDENTITY`, materialized-view `WITH [NO] DATA`, the sequence and identity options Snowflake has no grammar for, and identity `GENERATED ALWAYS`, which used to render as a plain `IDENTITY(1, 1)`); and `SnowflakeCreateMaterializedViewExpression` can be serialised and deserialised again, because `get_params()` emitted both the Snowflake and the core spelling of every field, which made serialising any instance raise.
